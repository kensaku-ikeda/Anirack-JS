# PR レビューのルール

## 流れ

1. PR を作ったら、続けて `/code-review low --comment <PR番号>` でレビューする
2. 指摘は PR の行コメントとして付く。学習者は GitHub 上で、自分の言葉で返信する
3. 直す指摘は、直してコミット・push し、返信に「〇〇で直しました」と書いて Resolve する
4. 直したら、もう一度 `/code-review low --comment <PR番号>` を回す
5. 重要度の高い指摘がなくなったら、マージしてよい

## 指摘の扱い

- 重要度の高い指摘（マージ前に直すべきもの）は、必ず対応する
- nit（細かい好みの指摘）は、直さなくてもマージしてよい
- 2回目以降のレビューで新しく出た nit には対応しない（イタチごっこを防ぐため）
- 直さないと決めた指摘には、理由を返信してから Resolve する
- 意味が分からない指摘は、少し調べてから「どこまで分かったか」を添えて質問する

## レビューの書き方

- CLAUDE.md の「コードレビュー」のルールに従う。何が問題か、なぜ問題かを言葉で書き、そのまま貼れる修正コードは書かない
- 学習者の返信に、代わりに返信しない。学習者の質問には、CLAUDE.md の「ヒントの出し方」に従って答える

## レベル

- 今は low（確信のある重要な指摘だけ）
- 物足りなくなったら、学習者と相談して medium に上げる
