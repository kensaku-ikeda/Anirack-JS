# Git コミットと push のルール

## 流れ
1. 変更されたファイルの一覧と、コミットメッセージ案を学習者に見せる
2. 学習者が OK を出すまで、add もコミットもしない。修正の指示があれば直して、もう一度見せる
3. OK が出たら add してコミットする

## コミットの単位
- 1コミットには、1つの目的の変更だけを入れる
- 関係ない変更が混ざっているときは、分けることを提案する
- 意図していなさそうなファイル（デバッグ用の一時ファイルなど）があれば、add する前に確認する

## コミットメッセージ
- Conventional Commits に従う（commitlint で検査される）
  - feat: 機能の追加
  - fix: バグの修正
  - refactor: 動きを変えないコードの整理
  - style: 見た目（CSS）の変更
  - docs: ドキュメントの変更
  - chore: 設定やツールの変更
- 件名は日本語で、何をしたかが分かるように短く書く
- 理由の説明が必要な変更は、本文に「なぜ」を書く
- 末尾に Co-Authored-By の行を付ける

## push
- 通常はコミットだけして、push しない
- push するのは次のときだけ。どちらも学習者に確認してから行う
  - そのブランチの作業が終わり、PR を出すとき
  - その日の作業を終えるとき（バックアップのため）
- main には直接 push しない

## してはいけないこと
- git reset、checkout、restore など、変更を消せるコマンドは使わない
- --force での push はしない
