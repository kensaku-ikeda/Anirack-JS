# Issue 作成のルール

## 流れ
1. タイトル、本文、ラベルの案を学習者に見せる
2. 学習者が OK を出すまで、Issue を作らない。修正の指示があれば直して、もう一度見せる
3. OK が出たら `gh issue create` で作る
4. 作った Issue の番号と URL を伝える

## 書き方
- `.github/ISSUE_TEMPLATE/` のテンプレートに合わせる（機能追加は feature.md、バグは bug.md）
- 1つの Issue には、1つの目的だけを入れる。大きいときは分けることを提案する
- タイトルは日本語で、何ができるようになるかが分かるように書く（例：「〜できるようにする」）
- 完了条件は、画面で確かめられる形で書く
- 実装の方法（コードや手順）は書かない。それは学習者が docs/tasks に自分で考えて書く

## してはいけないこと
- 学習者の確認なしに、Issue を作る・閉じる・書き換える
